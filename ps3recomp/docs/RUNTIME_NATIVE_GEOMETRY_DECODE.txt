Native geometry stream decoding — experimental data-level stage

native_geometry_decode.h implements a complete stream-decoding job over explicit
input/output spans, without SPU registers, LS addresses, guest dispatch, allocation
or callbacks. The owner retains those spans until completion. The current x86
implementation requires AVX2/FMA and the title's round-toward-zero, DAZ/FTZ mode.
The title's existing ISA dispatch preserves its original path on other hosts.

Inputs
- Packed big-endian xyz float32 positions,12 bytes per vertex. Their bits are
  preserved, including signed zero and special float encodings; w is1.0.
- Optional interleaved32-bit directions, explicit stride and byte offsets:
  signed11-bit x in bits0..10, signed11-bit y in11..21, signed10-bit z in22..31.
  Convert exactly to x/1024,y/1024,z/512, then FMA with the original bit-exact
  scale[3f801002,3f801002,3f802008] and bias[3a001002,3a001002,3a802008].
  This preserves the original asymmetric normalized mapping, including its
  rounded endpoints. It is not replaced with a similar-looking normalization.
- Explicit vertex count, including any padding required by the caller's format.

Outputs
One16-byte float4 position stream and up to three float4 direction streams.
Output storage can be host order or big endian. This lets future consumers use
native floats, while the current title adapter publishes bytes to the existing
downstream geometry path. Validation rejects overlapping outputs/inputs and
short spans before any output write. All allocations and completion ownership
remain outside the pure arithmetic/format kernel.

Bleach adapter
native_geometry_decode_plan.h decodes the descriptor into a complete plan and
stages descriptor updates before executing. It accepts primary format0 and an
absent/no-op secondary stream or the audited generic packed-direction format.
It checks counts, stride, tags, output slots, bounded private memory, callbacks
and aliases. Partial-attribute mode (header bit4) and unknown formats fall back
before output publication. Complete-stage decoding replaces only the observed
top-level0x408 call to0x9828, not arbitrary other calls into that function.

The original caller reloads r3/r4/r5 before calling7F58. That next stage consumes
those arguments plus callee-saved state; volatile scratch registers and the
returned callee's private stack are not the geometry result. Runtime verification
checks the return link/PC, stack pointer, callee-saved registers, execution status
and every private-memory byte outside the dead stack region. It checks geometry
outputs, all descriptor bytes and unrelated memory, rather than merely comparing
an isolated math loop. Output/input/descriptor spans cannot alias that stack.
The adapter still publishes into the job's private LS-backed buffers: this is a
data-level decoding stage, not yet a wholly native geometry submission pipeline.

BLEACH_NATIVE_DECODE=1 enables the experimental adapter; default remains0.
BLEACH_NATIVE_DECODE_VERIFY=N performs one differential check perN accepted
calls per worker. Verification is diagnostic only and excluded from FPS runs.
BLEACH_GEOMETRY_CONTRACT_CAPTURE=start_ms:duration_ms:path records at most32
diverse before/after examples of each of three phases for offline validation.
Those snapshots are oracles only; no snapshot cache is used during gameplay.

The later partial-attribute-mode/alias guard refinement has separate validation;
do not silently attribute earlier hashes or timings to a later executable.

test_native_geometry_decode.c uses guard-page inputs to catch overreads, golden
direction values from the original output, both output byte orders and invalid
spans/aliases whose rejection must leave all outputs unchanged.

Next structural work

triangle processing and ordered publication. The existing typed skinning kernel

in the title's same-executable A/B reports, not inferred from fewer instructions.
