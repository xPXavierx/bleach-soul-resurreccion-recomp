Ordered native recording — experimental Windows backend

rsx_native_recording.h separates CPU preparation from D3D12 command recording.
RSX_NATIVE_RECORDING=1 enables one worker; default0 retains synchronous use.
The producer owns guest decoding, geometry fetch, shader/resource preparation,
uploads and cache mutation. The consumer alone records prepared draws and
auxiliary commands and owns the command-list binding cache. This does not
replace the full SPU geometry producer or implement pose/camera interpolation.

Protocol and ownership
- Draw packets and copy locations, barriers, clear colors, viewports, scissors,
  root constants and bindings are copied into value records. No stack argument
  or dispatcher/vertex scratch pointer crosses the queue boundary.
- Resource pointers, mapped upload bytes and GPU descriptors remain leased
  through the existing frame/submission lifetime. CPU recording completion is
  NOT GPU completion and does not acknowledge guest fences or free GPU data.
- Before Close/ExecuteCommandLists, the CPU drains all earlier recording work.
  Existing actual GPU fences still govern allocator/ring/texture retirement.
  Reset and destruction cannot race the recorder. Query operations are ordered
  with the draws/copies they measure.
- CPU RTV/DSV descriptor replacement drains pending reads and invalidates the
  recording cache's target bindings. Shader-visible tables already use separate
  immutable submission slots. A partial cube upload's destination is retired
  through the GPU fence rather than released while earlier copies reference it.
- Auxiliary image transfers now update the same binding cache as normal draws;
  raw state changes no longer bypass that ownership boundary.

Queue
A bounded SPSC ring stores392-byte records,4096 entries by default. The backend
already serializes its preparation owner, including movie/guest handoffs.
One publication per16 commands coalesces notifications; drains publish tails.
The worker sleeps on a retained auto-reset event, without a polling spin loop.
Interlocked publication/consumption orders entry access. Full capacity applies
backpressure; no draw is dropped. The progress wait also observes worker death.
The worker publishes consumed positions after finishing entry access, in batches
of at most64. Shutdown drains, wakes, joins and then releases queue storage.

RSX_RECORD_QUEUE_CAPACITY=32..4096 supports bounded pressure tests. It is not a
performance-tuning recommendation. Only the implemented backend's command subset
is represented (up to4 barriers,8 root constant words,4 color targets, no clear
rectangles). Callers currently obey these bounds; unsupported extensions fail
explicitly instead of truncating commands. Extend the protocol when introducing
new backend operations. Other graphics backends are unchanged.

Evidence available before performance decision
test_native_recording.c calls the real queue/dispatcher against a slow mock
command recorder: copied stack inputs, ordered constants/draws, ring wrap,
capacity waits, drain and stop/restart in both modes.40,000 asynchronous
commands consumed across two cycles;1,248 capacity waits in the recorded run.
This test is about CPU command order, not GPU completion.

Production GPU tests with capacity32:8 shader/constant/scissor checks,
14 submission/resource/fence checks,4 depth-content checks all passed. The
requested D3D validation layer was unavailable(0x887A002D); pixels and resource
behavior were checked through readback, not by claiming validation-layer success.

dump_present_samples. Build213 also emits the drained summary there. Audit212

pass. Clean same-build performance comparisons are recorded separately.
